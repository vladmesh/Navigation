# 0001. Сетка координат в зоне отрисовки

- Status: accepted
- Epic: 01 / 8
- Date: 2026-10-23
- Release branch: release/epic-01

## Context

На основной карте (`Drawing/uberpainter.cpp`, класс `UberPainter`, создаётся в
`mainwindow.cpp:56`) есть координатная сетка, но читать координаты по ней нельзя:

- Сцена пересоздаётся раз в секунду по таймеру `paintingTimer` (GUI-поток):
  `run()` → `updateView()` → `graphicsScene->clear()` → `drawCoordinatesNet(minX, minY, maxX, maxY)`.
- `drawCoordinatesNet` рисует линии с фиксированным шагом 50 м по bbox объектов (±500 м),
  а не по видимой области. При сильном отдалении линии сливаются в серую заливку, при
  приближении на экран попадает одна линия или ни одной.
- Баг границ: в `drawCoordinatesNet` строка `maxX -= 50` повторяется дважды, `maxY` не
  сдвигается (uberpainter.cpp:70–73). Сетка несимметрична относительно объектов.
- Подписи не привязаны к линиям: это 8 равных долей видимой области
  (`visibleArea.width()/8`), значения дробные и часто в экспоненциальной записи
  (`QString::number(x)` даёт `5.12e+05` для UTM-easting).
- `updateCoordinates()` дублирует код подписей из `drawCoordinatesNet` и при панорамировании
  удаляет **все** `QGraphicsTextItem` сцены, включая подписи линейки расстояния/азимута
  (правая кнопка мыши).
- Ось Y инвертирована (`scale(1, -1)` в конструкторе). Текст сейчас отражают вручную
  (`mirrorTransform`) и масштабируют шрифт через `10.0 / transform().m11()`.
- При зуме колесом (`wheelEvent`) подписи не обновляются (вызов `updateCoordinates()` закомментирован).

Координаты сцены — метры UTM (easting по X, northing по Y), значения порядка
10⁵–10⁶ (X) и 10⁶–10⁷ (Y).

Вне скоупа: схема судна `MyGraphicView` (`Drawing/mygraphicview.cpp`, закомментированный
`drawGrid`), `SideGraphicView`, перевод в lat/lon.

Ограничения: Qt 6, C++17, qmake `Ship.pro`, целевая платформа Windows (MinGW/MSVC).
В `main` нет отдельного тестового проекта и CI; ветка `ci/minimal` (ведёт другой агент)
добавляет `Test/unit/unit.pro` и `.github/workflows/pr-ci.yml`, но в `main` ещё не влита.

## Decision

Решения человека (2026-10-23, см. `docs/sessions/2026-10-23-epic-01-architect-plan.md`):
только `UberPainter`; координаты — метры UTM; адаптивный шаг по ряду 1–2–5×10ⁿ; подписи
в метрах у линий, читаемые при инверсии Y и любом зуме; сетка всегда включена, без
переключателя; unit-тест на расчёт шага; исправить баг границ и убрать дубль `updateCoordinates`.

### 1. Чистая математика сетки — `Drawing/gridmath.h/.cpp`

Только стандартная библиотека (`<cmath>`, `<vector>`), без заголовков Qt и без `QObject`. Пространство имён `GridMath`:

```cpp
namespace GridMath {
// Наименьший шаг из ряда {1, 2, 5} × 10^n (n — любое целое), при котором
// span / step <= maxLines. span <= 0, NaN/inf, maxLines < 1 → 0.0 (сетку не рисовать).
double niceStep(double span, int maxLines = 10);

// Значения линий, кратные step, в [min, max] (включительно, с допуском 1e-9*step).
// Первая линия = ceil(min/step)*step. step <= 0, min > max, не-конечные → пустой вектор.
// Защита: не более maxCount значений (по умолчанию 1000), иначе пустой вектор.
std::vector<double> gridLines(double min, double max, double step, int maxCount = 1000);

// Число знаков после запятой для подписи: 0 при step >= 1, иначе -floor(log10(step)).
int labelDecimals(double step);
}
```

Свойство `niceStep`: для любого конечного `span > 0` число интервалов `span/step`
лежит в (4, 10] (соседние значения ряда отличаются не более чем в 2,5 раза). Это и есть
«~5–10 линий на видимую область». Шаг считается через `10^floor(log10(span/maxLines))`
с выбором мантиссы 1/2/5 и проверкой на погрешность (значение должно быть ровно
`m × 10^n`, без хвостов вида `199.99999`).

### 2. Отрисовка в `UberPainter`

- Новый приватный метод `drawGrid()` заменяет `drawCoordinatesNet(...)` и
  `updateCoordinates()`; оба старых метода и их объявления удаляются.
- Область сетки — видимая область `mapToScene(viewport()->rect()).boundingRect()`,
  расширенная на один шаг с каждой стороны; bbox объектов для сетки не используется
  (баг `maxX -= 50` исчезает вместе с кодом; `setSceneRect` в `updateView` не меняется).
- Шаг один для обеих осей (квадратные ячейки):
  `step = GridMath::niceStep(min(visible.width(), visible.height()), 10)`.
  По короткой стороне окна 5–10 линий, по длинной пропорционально больше.
- Линии: `QGraphicsLineItem`, косметическое перо (`QPen` с `setCosmetic(true)`, ширина 0/1 px,
  светло-серый), `zValue` ниже треков и объектов (например, −10).
- Подписи: `QGraphicsSimpleTextItem` с флагом `QGraphicsItem::ItemIgnoresTransformations`,
  фиксированный размер шрифта в пунктах (≈8 pt). Флаг сам компенсирует `scale(1,-1)` и зум:
  `mirrorTransform` и `10.0 / transform().m11()` для сетки не используются.
  - Easting (X): у каждой вертикальной линии, у нижнего края видимой области.
  - Northing (Y): у каждой горизонтальной линии, у левого края видимой области.
  - Формат: `QString::number(v, 'f', GridMath::labelDecimals(step))`, без экспоненты,
    без единиц у каждой подписи (единицы — метры, см. документацию).
  - Подпись на экране смещается на несколько пикселей внутрь от края и от линии, чтобы не
    перекрываться линией; смещение задаётся в пикселях (через `ItemIgnoresTransformations`
    + `setPos` в координатах сцены линии на краю видимой области).
- Все элементы сетки создаются как дети одного `QGraphicsItemGroup*` (или хранятся в
  отдельном списке) — член класса `gridGroup`. Перерисовка сетки удаляет только эту
  группу/список; остальные элементы сцены (треки, линейка расстояния) не трогаются.
  После `graphicsScene->clear()` указатель обнуляется до создания новой группы
  (`clear()` удаляет элементы сам — двойного удаления быть не должно).
- Когда вызывается `drawGrid()`:
  - из `updateView()` после `clear()` (раз в секунду), на месте старого `drawCoordinatesNet`;
  - при любом сдвиге вида в `scrollContentsBy` (пан мышью, полосы прокрутки, клавиши,
    `centerOn`); заменяет вызов в `mouseMoveEvent` (ревью Task 02, раунд 1);
  - после масштабирования в `wheelEvent`;
  - в `resizeEvent` (переопределить).
- Блокировка: `updateView()` держит `sceneMutex` (нерекурсивный `QMutex`). `drawGrid()`
  сам мьютекс не берёт; вызовы из обработчиков событий берут `QMutexLocker(&sceneMutex)`
  вокруг вызова. Повторного захвата внутри `updateView()` быть не должно. Обработчики, которые
  Qt может вызвать синхронно изнутри `updateView()` (`scrollContentsBy`, `resizeEvent` из
  `setSceneRect`), берут мьютекс через `try_lock` и при неудаче пропускают перерисовку:
  `updateView()` рисует сетку сам после `setSceneRect`.
- Деструктор сначала отвязывает сцену (`setScene(nullptr)`) и обнуляет `gridGroup`, затем удаляет
  сцену; `drawGrid()` ничего не делает без привязанной сцены.
- Сетка рисуется всегда, в том числе пока нет ни одного объекта (видимая область есть всегда).

## Alternatives considered

- Фиксированный шаг 50 м с подстройкой bbox — не решает зум: на 10 км линии сливаются.
- Рисовать сетку в `drawBackground()`/`drawForeground()` через `QPainter` — меньше элементов
  сцены и нет перерисовки на каждом пане, но текст под `scale(1,-1)` пришлось бы
  отражать вручную и перенести логику из модели сцены в рендер; оставлено как возможная
  оптимизация, если `ItemIgnoresTransformations` окажется медленным.
- Lat/lon-градусная сетка — человек выбрал метры UTM; сетка UTM совпадает с осями сцены.
- Переключатель вкл/выкл в меню — человек отказался: сетка всегда включена.
- Шаг по длинной стороне окна — на широком экране по короткой стороне остаётся 2–3 линии.

## Risks

- Пересоздание сотен элементов при каждом событии пана → лаги. Митигация: `gridLines`
  ограничен `maxCount`; при 5–10 шагах на короткую сторону элементов десятки; если тестер
  увидит лаги — перейти на `drawBackground` (альтернатива выше) новым таском.
- Погрешность float: `ceil(min/step)*step` на UTM-значениях ~5·10⁶ даёт хвосты
  `5123400.0000001` → подпись с мусором. Митигация: округление в `gridLines` до кратного шага,
  форматирование через `labelDecimals`, unit-тест на большие значения.
- `ItemIgnoresTransformations` и инверсия Y: якорь текста — левый верх в координатах
  устройства; подпись может уйти за край вьюпорта. Митигация: критерий тестера «подписи видны
  у всех четырёх краёв при зуме от 1 м до 10 км на экран».
- Блокировки `sceneMutex` из обработчиков событий — риск дедлока при неверном вложении.
  Митигация: правило выше, проверка ревьюером.
- В `main` нет `Test/unit/` и PR-CI (они в `ci/minimal`). Митигация: таск 01 создаёт
  свой тестовый `.pro`, не конфликтующий с `Test/unit/unit.pro`; когда `ci/minimal`
  будет влита в `main`, `architect-revision` подтягивает `main` в `release/epic-01`.
  Закрыт 2026-10-23: `main` влит в `release/epic-01` через PR #10, `tst_gridmath` добавлен в PR-CI.

### Task 01: Чистая функция расчёта шага сетки + unit-тест

- Status: done (PR #5, merged into release/epic-01 by architect-revision 2026-10-23)
- Scope: новые `Drawing/gridmath.h`, `Drawing/gridmath.cpp` (добавить в `SOURCES`/`HEADERS`
  `Ship.pro`); новый тестовый проект `Test/unit/gridmath/tst_gridmath.pro` +
  `tst_gridmath.cpp` (QtTest, `QT = core testlib`, без `gui`/`widgets`, компилирует
  `Drawing/gridmath.cpp` напрямую). Если на момент таска в release-ветке есть
  `.github/workflows/pr-ci.yml` — этот таск явно разрешает добавить в него шаги сборки и
  запуска `tst_gridmath` (по образцу существующих unit-шагов); иначе `.github/` не трогать.
  `UberPainter` не меняется.
- Acceptance criteria:
  - [x] `gridmath.h/.cpp` не включают ни одного заголовка Qt; API ровно как в Decision §1.
  - [x] `niceStep`: 1000→100, 999→100, 1001→200, 50→5, 12345→2000, 2.5→0.5, 7→1,
        0.07→0.01, 1e7→1e6; результат всегда вида {1,2,5}×10ⁿ без float-хвостов.
  - [x] `niceStep` для 0, отрицательного, NaN, ±inf, `maxLines<1` возвращает 0.
  - [x] Свойство: для ≥1000 значений span в диапазоне 1e-2..1e8 (логарифмическая
        развёртка) `span/step` ∈ (4, 10].
  - [x] `gridLines(5123401.3, 5124399.0, 200)` = {5123600, 5123800, 5124000, 5124200}
        точно (сравнение `==` после округления, без хвостов); `gridLines` на границах
        включает кратные min/max; некорректный ввод и превышение `maxCount` → пусто.
  - [x] `labelDecimals`: 100→0, 1→0, 0.5→1, 0.01→2.
  - [x] `Ship.pro` собирается (qmake + make) с новыми файлами; `tst_gridmath` собирается и
        проходит под `QT_QPA_PLATFORM=offscreen`.
- Verification: `tst_gridmath` (PR-CI шаг, если workflow есть; иначе локально
  `qmake Test/unit/gridmath/tst_gridmath.pro && make && ./tst_gridmath` и в отчёте
  «no workflow yet»); ревьюер — по коду и тестам.
- Issue / PR: #4, #5

  вне ~1e-21..1e23 (fallback на `std::pow`) не проверена, вне диапазона UTM.

### Task 02: Адаптивная сетка и подписи в UberPainter

- Status: done (PR #12, merged into release/epic-01 by architect-revision 2026-10-23)
- Depends on: Task 01 (смёржен в release/epic-01).
- Scope: `Drawing/uberpainter.h`, `Drawing/uberpainter.cpp`. Удаляются
  `drawCoordinatesNet`, `updateCoordinates`; добавляются `drawGrid()`, член `gridGroup`
  (или список элементов сетки), переопределение `resizeEvent`. Ничего вне `UberPainter`.
- Acceptance criteria:
  - [x] В коде нет `drawCoordinatesNet`, `updateCoordinates`, строк `maxX -= 50`; нет
        подписей, рассчитанных как доли видимой области (`/8`).
  - [x] Шаг берётся только из `GridMath::niceStep(min(w, h), 10)`, линии — из
        `GridMath::gridLines`; своей арифметики шага в `UberPainter` нет.
  - [x] Сетка покрывает всю видимую область у всех четырёх краёв (нет пустых полос), в том
        числе когда объектов нет и когда объект один.
  - [x] По короткой стороне окна `span/step` ∈ (4, 10] (Decision §1), то есть видно 4–11 линий,
        при любом зуме (1 м … 10 км на экран);
        шаг меняется скачком по ряду 1–2–5 при зуме колесом сразу, без ожидания таймера.
  - [x] Каждая подпись стоит у своей линии и равна её координате: X (easting) у нижнего
        края, Y (northing) у левого края; формат `'f'` с `labelDecimals(step)`, без экспоненты
        (например, `512400`, `5123600`).
  - [x] Подписи не зеркальные и одного экранного размера при любом зуме
        (`ItemIgnoresTransformations`); для сетки не используются `mirrorTransform` и
        `transform().m11()`.
  - [x] Пан мышью и ресайз окна сразу перестраивают сетку и подписи; подписи линейки
        расстояния/азимута (правая кнопка) при пане не пропадают.
  - [x] Перерисовка сетки удаляет только элементы сетки; нет двойного удаления после
        `graphicsScene->clear()`; `sceneMutex` не захватывается повторно (ревьюер).
  - [x] Линии сетки лежат под треками/объектами (`zValue`), перо косметическое.
  - [x] `Ship.pro` собирается на Windows без новых предупреждений в `uberpainter.cpp`.
- Verification: ревьюер — по коду; тестер — вручную на Windows-сборке: зум колесом от
  максимального приближения до отдаления, пан, ресайз, режим линейки, запуск без
  подключённых источников; скриншоты в отчёт тестера.
- Issue / PR: #11, #12
- Scope note: в PR также `Test/app_sources.pri` (+`gridmath.cpp/.h`): зеркало `Ship.pro` для
  `tst_critical`, без него PR-CI не линкуется. Логики не меняет; принято ревьюером.
- Leftovers (приняты как риск, не новые таски этого эпика):
  - Пустая сцена: без объектов `updateView()` передаёт в `setSceneRect` `±DBL_MAX`/`-inf` (было до
    эпика; Decision §2 запрещает менять `setSceneRect`). Сетка рисуется по видимой области, но
    область задана этим состоянием. Тестер проверяет запуск без источников на Windows. Кандидат в
    задачу следующего эпика.
  - Производительность: `scrollContentsBy` перестраивает сетку на каждое изменение полосы прокрутки,
    до ~4 перестроений на одно движение мыши при пане. Тестер оценивает лаг при пане; при лаге —
    схлопывание через отложенный вызов (ревью раунд 2, finding 1).
  - Существующие до эпика: висячие указатели линейки после `clear()`, двойной сдвиг при пане
    (ручной + `ScrollHandDrag`), подписи X могут налезать в очень узком окне.
